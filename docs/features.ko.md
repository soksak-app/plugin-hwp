# 기능

[English](features.md)

- [o] H1 — P1: rhwp를 bundle한다. `scripts/build-vendor.mjs`는 정확한 devDependency `@rhwp/core` 0.8.7(MIT)의 `rhwp.js`와 `rhwp_bg.wasm`을 `ui/vendor/`에 복사하고, 그 라이선스와 rhwp가 0.8.7에 나열한 third-party 라이선스(`vendor/rhwp-0.8.7-THIRD_PARTY_LICENSES.txt`)를 담은 `rhwp.LICENSE.txt`를 함께 두며, `--check`는 커밋한 파일이 다르면 실패한다. 2026-10-08에 완료했다. `make test`가 그 검사를 실행한다.
- [o] H2 — P1: core checklist 항목 F102.4와 F109를 위해 프로젝트의 `.hwp`나 `.hwpx` 파일을 열고 쪽을 그린다. `surface.opens`는 `hwp`와 `hwpx`를 선언하고, page는 files sidecar 0.0.5 이상의 `readBytes`로 파일을 읽어 각 쪽을 rhwp의 SVG로 그리며, 탭 이름을 파일 이름으로 한다. 2026-10-08에 완료했다. `test/hwp.test.mjs`가 문서를 열어 글과 쪽을 찾고, core 창 검사 `e2e/hwp.test.mjs`가 두 host에서 파일 tree의 `.hwp` 파일을 Enter로 연다.
- [o] H3 — P1: 커서에서 본문 글을 고친다. 클릭은 `hitTest`로 커서를 놓고, 커서의 입력 칸이 입력한 글, 입력기 조합, 편집 키를 받으며, 모든 편집은 `hwp.edit`을 실행한다. 커서의 x는 `getCursorRect`에서, 위쪽과 높이는 `getCursorRectOnLine`에서 가져온다. `getCursorRect`는 글이 있는 줄에서 기준선과 높이 0으로 답하기 때문이다. Red: 다시 그리기가 초점을 가진 입력 칸을 새 쪽으로 옮겨 `the input field keeps the focus while edits draw the pages again`이 실패했고, `the caret has the height of its line in a paragraph with text`가 높이 0으로 실패했다. Green: 둘이 통과하고, core 창 검사에서 네이티브 키가 두 host에서 글을 넣는다.
- [o] H4 — P1: page가 읽은 version으로 `writeBytes`를 써서 파일 자신의 형식으로 저장하고, rhwp가 내용을 잃는다고 보고한 저장은 거절하며, 디스크의 변경을 따르고, 실패는 `tab.error`로 보인다. 2026-10-08에 완료했다. 저장과 충돌 테스트가 통과하고, core 창 검사에서 Command-S가 파일을 쓰며 다시 읽어도 편집이 남는 것을 두 host에서 확인했다.
- [ ] H5 — P1: CI와 release workflow를 더한다. `ci.yml`은 macOS runner에서 `make test`를 실행하고, tag `v*`는 `release.yml`을 실행하며, 이는 선언한 core release의 `sok`으로 plugin을 pack한다.
- [ ] H6 — P1: 버전 0.0.1을 릴리스하고 registry에 올린다. 영역의 plugin 문서를 내보내는 core 릴리스(core F111)와 files sidecar 0.0.5 이상을 요구한다.
- [ ] H7 — P2: 쪽을 카드 폭에 맞춘다. 카드보다 넓은 쪽은 그 폭으로 줄이고, 클릭과 커서도 같은 배율을 쓴다.
- [ ] H8 — P1: 사용자 승인을 받아 activation tier 검사로 커서의 한글 입력기 조합을 같은 창의 AppKit text view와 비교해 확인한다.
- [~] H9 — P1: H2, H3, H4의 표면 대신 rhwp의 편집기로 편집한다. plugin은 rhwp tag `v0.8.7`에서 고치지 않고 빌드한 `rhwp-studio`를 담고, 페이지는 그것을 문서 영역(core F111)에 보이며, embed protocol의 `loadFile` 요청으로 파일을 보내고 `exportHwp` 또는 `exportHwpx`의 bytes를 저장한다. 선택, clipboard, 되돌리기, 입력기, 서식, 표는 편집기의 것이다. H2, H3, H4가 그린 페이지와 그 test는 지운다.
  - [o] H9.1 — P1: `rhwp-studio`를 `ui/studio`로 빌드한다. `scripts/build-studio.mjs`는 빌드에 필요한 rhwp `v0.8.7`의 파일을 checkout하고, 다른 commit을 거부하고, `@rhwp/core` 0.8.7의 WebAssembly package를 두고, `rhwp-studio`의 빌드 script를 고치지 않고 실행한다. `make studio`가 그것을 실행하고, `make pack`과 release workflow는 pack 전에 빌드한다. `docs/studio.md`는 빌드와 이후 rhwp tag로의 갱신을 설명한다. 2026-10-08 완료: `make studio`가 `COMMIT`이 정한 commit의 rhwp `v0.8.7` checkout에서 편집기를 `ui/studio/`(54 MB)에 쓴다.
  - [o] H9.2 — P1: 편집기 페이지에서 Command-S와 미저장 변경을 알린다. 빌드한 페이지에 더한 `ui/studio-host.js`는 Command-S에 `save`를, 입력 event나 편집기의 응답 뒤 `window.rhwpStudio.automation`의 `isDirty`가 바뀌면 `modified`를 보낸다. `rhwp-studio`에는 최상위 페이지를 위한 변경 event가 없기 때문이다. 2026-10-08 완료: `test/studio-host.test.mjs`가 4개 test를 통과하고, 두 host에서 편집기 페이지가 보낸 응답과 message를 표면 페이지가 받는다.
  - [o] H9.3 — P1: 편집기를 문서 영역 `studio`에 보이고, embed 요청 `ready`, `loadFile`, `exportHwp`, `exportHwpx`, `notifySaved`로 파일을 열고 저장하고 다시 읽으며, `hwp.document`, `hwp.save`, `hwp.reload`, `hwp.request`를 둔다. H2, H3, H4의 페이지와 그 test, H1이 vendor한 `rhwp.js`는 지운다. 2026-10-08 완료: `test/hwp.test.mjs`가 가짜 편집기 영역으로 8개 test를 통과하고, `make test`가 exposure와 engines 검사와 함께 12개 test를 통과하며, 두 host가 `docs/plan.hwp`를 편집기에서 1쪽으로 연다.
  - [ ] H9.4 — P1: 두 host에서 편집기를 관측한다. 트리에서 파일을 열고, 네이티브 키로 고치고, drag와 Shift로 글을 선택하고, 복사해 붙이고, Command-S로 저장하고, capture로 밝은 테마와 어두운 테마를 확인한다.
  - [o] H9.5 — P1: 편집기에 선택 영역이 있는지 알린다. `ui/studio-host.js`는 automation context의 `hasSelection`이 바뀌면 `selection`을 보내고, `hwp.document`는 그것을 `selection`으로 알리므로, 창 검사는 pointer나 Shift로 만든 선택을 기다린다. Red: message와 `selection`이 없어 `a pointer release that selects text posts selection, and a key that removes it posts it again`, `a selection message of the editor page sets the selection of hwp.document`, `the surface loads the editor page of the package and opens the file in it`가 실패했다. Green: `make test`가 14개 test를 통과한다. 2026-10-08 완료.
  - [o] H9.6 — P1: 이 저장소의 문서에서 plugin을 plugin이라고 부른다. `docs/studio.md`, README, `Makefile`, checklist는 그것을 더 이상 package나 archive라고 부르지 않는다. 2026-10-08 완료.
